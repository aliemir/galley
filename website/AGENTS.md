# website/

The public site: **privacy policy** and **support page**, the two URLs App
Store Connect requires and refuses to accept unless they resolve. A Cloudflare
Worker serving static assets out of `public/`, styled with Tailwind v4.

Separate from `backend/` on purpose — this is public, cacheable, and has no
secrets or bindings. Backend API work belongs in `backend/`, not here.

## Layout

| Path | What |
|---|---|
| `public/` | Everything served. `index.html` is `/`, `privacy.html` is `/privacy`, etc. |
| `input.css` | Tailwind source. **The only stylesheet you edit.** |
| `public/style.css` | Generated by Tailwind from `input.css`. Git-ignored — never edit or commit it |
| `wrangler.jsonc` | Worker config. `assets.directory` points at `public/` |

## Commands

```bash
npm run dev        # builds CSS once, then wrangler dev
npm run deploy     # builds CSS once, then wrangler deploy
npm run dev:css    # tailwind --watch, run alongside `npm run dev` while restyling
npm run build:css  # one-off minified build
```

`dev` and `deploy` both run `build:css` first. A bare `npx wrangler deploy`
does not — it ships the site with a missing stylesheet, which looks like a
broken page rather than an error. Use the npm scripts.

## Content

- The privacy policy text comes from `privacy-policy-template/` at the repo
  root. Fill in the bracketed placeholders there, then render it into
  `public/privacy.html`.
- Whatever URLs end up live must be written back into
  `store-metadata/listing.json` under `urls.support` and `urls.privacyPolicy`.
  App Review checks that they load.
- No build step beyond Tailwind. These are hand-written HTML files, not a
  framework — keep it that way unless there is a reason.

## Naming

`wrangler.jsonc` and `package.json` both carry `"name": "website"`. That is the
template placeholder; `./rename.sh` at the repo root rewrites it to
`<slug>-website`. Do not hardcode a real app name here.
